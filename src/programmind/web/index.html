Privacy

What leaves this machine, what never does, and what is written where. This page is a description, not a setting.

What leaves this machine

One thing: the prompt each agent builds, sent to your company's AI gateway and answered by the model named in Options. A prompt holds what that agent needs to answer:

  • the question or the topic you typed, and your answers to the clarifying questions;
  • the sections of your vault the agent selected for that question, and one-line summaries of further pages;
  • the role profiles and the conduct note of the swim lanes being asked, and their KPI notes;
  • the earlier questions and answers of the same topic or thread, so a follow-up makes sense.

You can read the whole of it before it goes: the confirm screen lists every section that would be sent, with its size, and you can add or leave out any of them.

What never leaves it

  • The vault. It stays a folder on your disk. Only the sections an agent selected for one question travel, never the whole vault, and never a page nobody asked about.
  • Your work. Topics and threads are files next to this program's configuration. They are not in the vault and they are not sent anywhere.
  • The audit trail. One line per model call, with the counts and the durations, never the text.
  • Anything about how you use the site. No telemetry, no analytics, no crash reporting, no check for updates. The server listens on this machine only and answers nothing but its own page.

Writing into the vault

No agent writes into the vault on its own. When you close a topic or a thread you may ask for a note; the agent proposes the text and the place, you see exactly what would be written and where, and it is written only after you confirm.

Discarding leaves the vault untouched. The enrich command works the same way: it proposes, and writes only when you say so.

What the gateway does

Once a prompt reaches the company gateway, what happens to it is governed by your company's agreement with that provider, not by this program.

This program keeps no copy of a prompt beyond the topic or thread on this machine.

How the board is asked

Individual (default)
One call per ticked member, each answering alone, then one call that consolidates. Members cannot see each other, so disagreements stay visible.
Cost: one call per member, plus one.

Combined
One call receives every ticked profile, the KPI notes and the same knowledge, and writes all entries and the direction in one pass. One model writes them all and sees the earlier entries while writing the later, so fewer disagreements surface.
Cost: one call. Good for a quick first opinion, follow-ups and topics that concern few swim lanes.

In both modes the program checks that every member came back, that each entry names its own measures or tasks, and every citation.

Knowledge per member

6,000 tokens
What the slider caps: the sections each member receives in full - the shared core (project page, phase and gate definitions, the tasks active in the phase your question names) and the member's own sections.
On top, not counted by the slider: one line each for up to 20 further pages (at most 800 tokens), the sections you add below, and the KPI notes.
The estimate follows the slider.

Knowledge selection

AI assisted (recommended)
The model reads a list of candidate sections with their summaries and picks, per member, what that member needs, with a reason you can read.
Pro: picks by meaning, knows synonyms, improves as the vault grows.
Con: one extra call per question, about the size of one member call; the model can pick wrongly, so the picks are shown below before the board runs.
Cost: one call more.

Python only
The program ranks sections by how often the question's words and the member's own words appear, plus the page properties (lead, affected swim lanes, phase).
Pro: free, instant, the same result every time.
Con: literal; misses pages that say the same thing in other words; weaker as the vault grows.
Cost: none.
